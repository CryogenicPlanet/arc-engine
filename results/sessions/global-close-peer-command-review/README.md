# Command-bearing peers after facade deassociation — bounded review

**One concrete forced-path integration prerequisite remains: application termination can issue native Browser commands through GlobalBrowserCollection after facade deassociation but before the destructor fallback has removed that Browser globally.** This is a fresh native enumeration bypass, not an independent cached Browser pointer. No additional proven renderer cached-command defect was found. Queued logical notifications must not receive a speculative facade/native equality gate.

This review is of the UNAPPLIED private v2 physical-phase/core-endpoint composition against current live peers. It does not approve activation or change production. Another reader covers exact transport/composition/pipeline correctness. Existing cached-binding and original logical-token evidence supply the earlier known sessions limits.

## P2: reconcile forced-path termination command eligibility before activation

Exact live paths:

- **arc/api/arc_app_termination.mm:162–169**: fresh public tryToTerminate creates/gets state; if inactive it calls Begin. **31–46** sets the quit latch, retains completion and immediately calls Check. **71–88** obtains GlobalBrowserCollection and, without consulting any ArcBrowser facade, enumerates Browser pointers into UnloadController::RunBeforeUnloadForShutdown at77 and HandleBeforeClose at88. The denial route separately enumerates native ResetBeforeUnloadForShutdown at63–64. This is actual native work, not a retained callback DTO. **chromium/src/chrome/browser/ui/unload_controller.cc:508** immediately dereferences browser_->GetType and then can collect/process beforeunload tabs513–521.
- **chromium/src/chrome/browser/ui/browser_manager_service.cc:42–53**: Shutdown moves/pops the owning entry and removes the profile activation entry before destroying Browser. It does not first publish global OnBrowserClosed. Its constructor25–26 registers the global platform delegate; its native DidClose subscription94–95 only forwards at268–270 when that event actually occurs. The non-Android platform delegate forwards OnBrowserClosed directly to global removal(global_browser_collection_platform_delegate_non_android.cc20–22).
- **chromium/src/chrome/browser/ui/browser_window/internal/global_browser_collection.cc:37–41** returns its still-stored Browser vectors. Its removal is at**58–60**, on OnBrowserClosed. **chromium/src/chrome/browser/ui/browser_window/internal/browser_collection.cc:33–37,69–74** directly invokes enumeration callbacks for stored nonnull entries; it has no facade/destruction-state filter. Its observer only nulls entries after OnBrowserClosed49–54.
- The private hook is proposed at **chromium/src/chrome/browser/ui/browser.cc:357**, BEFORE the forced/direct fallback **358–364**. That later fallback reaches **chromium/src/chrome/browser/ui/unload_controller.cc:1123–1130**, which marks delete scheduled and notifies DidClose. A still-open forced Browser can therefore remain globally enumerable while the new app close callback runs, even though core has cleared its facade/native close-state bindings.

Consequence: a fresh/reentrant tryToTerminate from that app callback, with a nonnull completion, when no termination request is already active and the ordinary process/profile-manager admission check passes, can command the destructing Browser through global enumeration. Facade clearing alone does not revoke that route. This source path does not establish a runtime crash, UAF, all shutdown states, or original Arc's forced-path termination behavior.

**Narrow owner request:** Core/native plus App must establish and implement/review the supported command-eligibility contract for globally enumerable Browser instances during pre-fallback publication, or prove a supported caller/state invariant excluding this reentry. App owns these enumerated native command entries; core owns the authoritative destruction/association state. A generic queued-notification gate, renderer/WC purge, guessed registry reorder, blanket skip of all closing browsers or premature OnBrowserClosed is not justified by this finding. No particular new transport/query API is selected here.

Ordinary scheduled deletion is different: DidClose already occurred and global removal already ran before the posted physical destruction task. The finding concerns the proposed forced/direct-before-fallback interval. Profile manager ownership extraction alone is not global collection removal. Original normal collection/destructor proof does not establish original forced-path global membership or fresh termination behavior.
