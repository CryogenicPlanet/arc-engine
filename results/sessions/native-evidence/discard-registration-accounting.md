## Precise additional shared lifetime requirement

Both native paths retain the **real functional logical Impl** through their queued work. Current block retains SessionsDiscardState while owner/adapter delivery uses weak references; the staged accounting adapter retains **CoreCloseState only**. Its header explicitly says that state owns no native contents/wrapper/delegate (`core_close_state.h:17–19`). These objects are not the functional logical WC/Media/DevTools graph. Current inactive early return additionally omits original fallback deferred peer retention/release.

Future integration therefore needs **post-PM, existing-only acquisition of the already-associated real logical handle**, after the surviving-binding check and before queued capture. The accepted live-registration task must strongly retain that acquired handle while keeping the selected registration weak and leaving capture after synchronous PiP reentry. The absent-registration branch needs the proved no-UI-count/no-finalize deferred retention/release behavior. Do not run that fallback through a UI pending wrapper, fabricate a fresh root, retain the ObjC facade as a stand-in, or substitute an accounting token for functional ownership.
