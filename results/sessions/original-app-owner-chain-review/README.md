## What the binding packet changes

It positively establishes a route that creates an actual ADKBrowserDelegate, pairs it with concrete ADK.BrowserDelegate table104187fd8, and invokes an incoming Browser protocol setter. If that Browser witness is10418c868, it reaches ChromiumBrowser's actual weak browserDelegate object/witness mutation and later callback witness+8. This narrows the old dynamic-binding gap; it does not leave the chain at mere conformance existence.

It does **not** establish who supplied10133f508's Browser object/witness or which numeric predicate branch the ordinary callback took. The cache lookup/update around delegate creator is not a complete delegate-cache ownership/disposal proof. Weak assignment to ChromiumBrowser cannot independently keep a delegate alive. Likewise the constructor's lazy actionSubject initialization is not proof of a live/cached subject at notification, its buffering flag, or persistent retained actions. The three earlier packet conclusions must remain conditional after this fourth edge is composed.

## Persistent Root owner remains open

The strongest proved field is:

    a live WebContentChromium instance → strong webView(ArcWebContents facade)

Conditional delegate storage can add an action/array→WebContentChromium edge if its receiver, branch and container lifetime are established. None of these packets proves a persistent outer owner/container survives the ordinary callback's local release and later drains/disposes correctly. Even accepting Core's separately established facade→logicalRoot shared edge, the missing persistent outer owner prevents concluding a transitive ordinary Root lifetime. A witness call, payload retain, lazy/buffer field name, conditional append or alternative Session array store cannot replace that proof.

**Next narrow boundary:** establish the incoming concrete Browser object/witness and relevant branch/epoch at10133f508 so the conditional assignment is attached to the ordinary Chromium callback path. After that, trace only the selected delegate's actionSubject getter1004eb4f8 to its actual stored subject owner and lifetime; then resolve the callback-time buffering branch or the selected subscriber's concrete storage/disposal. This is an evidence boundary description, not authorization to expand the whole Swift graph or run a new probe.
