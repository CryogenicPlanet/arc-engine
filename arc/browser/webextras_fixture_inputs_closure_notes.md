# Actual comparator input closure freezer

The actual owned `webextras_fixture_inputs.py` now discovers and freezes the comparator's local Python import closure. Shared comparator/proposal/normalization files remain untouched. No app/build/runtime was run.

`FILES` deliberately stays the four base inputs: comparator, ObjC metadata, callback table and freezer. Static AST traversal starts at the selected comparator and follows regular flat `.py` siblings under `tests/recorder`, including imports inside functions/classes and transitively imported siblings. It never imports those sources or searches `sys.path` for dependencies. Standard-library roots use the current interpreter's `sys.stdlib_module_names`; source siblings/packages shadowing an explicitly imported stdlib root are rejected. Missing/unknown local dependencies, local packages, relative imports and recognized dynamic loader/exec forms fail closed.

The current unmodified legacy comparator has no local helper imports, so it still freezes exactly4 inputs. The full normalization chain plus87be and callback correction discovers `download_identity.py`, function-local `google_q.py` and function-local `omnibox_receivers.py`, giving exactly7. Helpers are discovered, hashed, copied and rechecked automatically. No post-freeze helper copy is part of acceptance.

Before copying, every base/closure input is identified and hashed; after copying all original identities and frozen hashes/sizes are rechecked, and both source/frozen AST closures must match. Input components within the chosen resolved root and the root leaf itself reject symlinks; files must be regular. The manifest's file set must exactly equal recomputed frozen closure plus base inputs. The optional new `comparator_closure` field is validated when present. Existing clean four-file manifests without that field remain valid, including the unchanged actual native9 legacy snapshot. Verification uses frozen files only; later live helper mutation/removal does not affect a valid snapshot.

A review exposed an important bytecode issue: Python `-B` prevents writes but can still execute existing unchecked-hash `.pyc`. The freezer now requires exact inventories for **both** frozen executable import directories: recorder closure/`app_callbacks.inc`, and the frozen freezer's directory. Unexpected caches, flat bytecode, extensions, packages, extra source files or links are rejected before executable comparator capability checks and on every verification/comparison. The manifest must also be regular. The frontend owner separately changed its initial frozen-freezer loader to compile source bytes directly, so an unmanifested cached freezer cannot run before verification.

This is a bounded static sibling-import contract for the reviewed comparator, not an arbitrary-Python sandbox or a claim to seal the interpreter/standard-library environment. Explicit local package/dynamic loading requires a new reviewed policy; no guessed dependencies or normalization allowlists were added. The existing fixture capability result shape and unsupported/pending behavior are unchanged. Snapshot manifests may add closure metadata.

Validation:23 actual tests in `webextras_fixture_inputs_closure_test.py` pass. They cover legacy4 and old manifest compatibility, supported7 plus all4 actual frontend capability canaries, helper mutation/removal, live/frozen independence, transitive/function-local discovery without executing imported code, missing/unknown/sys.path-only modules, symlinks/path escape manifests, concurrent copy mutation, unchecked-hash bytecode and alternate import candidates. Durable actual CLI freeze/verify/compare and frontend4-canary evidence is under `logs/wp/webextras-fixture-inputs-closure/`; all snapshot helper files come from the actual freezer.
