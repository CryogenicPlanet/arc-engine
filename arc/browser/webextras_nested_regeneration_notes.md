# HELD minimal nested frontend regeneration proposal

**Sole proposed adoption route:** `webextras_nested_regeneration.patch` SHA256c6f87b82b3557fea5f14bdb11c3407a276a2215fa6fd198bab8a6a03893549c6 applies DIRECTLY to actual arc/tools/regen-patches.sh and adds arc/tools/regen-chromium-patches.py. Final helper SHA25646691c7ef274894bf8c0f8245f97c970566af9d8e4b9e8409b0eeff5b1321b2c. Lead ACK is required for only those two shared-tool paths. No sync-chromium.sh change, new applier API, or hand-written unified-diff header/hunk parser is proposed. The original sync already applies full-prefixed nested hunks through outer gitapply; real fixtures prove this.

This bounded proposal supersedes all historical970/d392/0f5 tool variants for adoption. Do not combine them with it. Their frozen proposals/tests/rejection reviews remain unchanged. They grew an unnecessary custom applier/parser; that scope was removed at the parent's explicit direction. No actual shared tools, real/alternate index, MANIFEST, maintained patch, Chromium source, lock/build/app/runtime/board state changed.

Manifest syntax remains `<patch basename> <outer Chromium relative leaf>` and ownership is exact-once. Existing hooks.h/window stay0004; new native bindings/dispatcher and all five frontend leaf paths belong once under0010-webextras.patch in the separately authorized integration. Only the existing third_party/devtools-frontend/src gitlink is supported. Outer HEAD gitlink, selected outer index gitlink and nested HEAD must match; nested root identity and indexed regular source paths are checked. NUL status is collected independently in both repositories, with submodule-ignore configuration overridden. No local symlink components, duplicate/escape paths, missing/unknown/untracked/conflicted/rename/delete changes or hidden index flags are accepted.

All Git reads have GIT_OPTIONAL_LOCKS=0. Explicit absolute outer GIT_INDEX_FILE is retained for outer queries only; nested Git uses its actual index. Relative/empty ALT and inherited GIT_DIR/GIT_WORK_TREE fail. Normal indexedITA entries are valid. The helper never stages or writes any real/alternate index; untracked sources fail even if manifest-listed. A new outer file created by original sync requires explicit authorized indexing before a later regeneration, unlike the old script's automatic real-index git add -N. This stricter requirement is part of lead ACK.

Generation uses trusted actual Git diff HEAD per owning repository with external diff/textconv/renames/color disabled. This intentionally preserves final staged+unstaged worktree bytes instead of the old unstaged-only view. Nested diffs receive full a/third_party/devtools-frontend/src/ and b/... prefixes. Git's own name-only output and gitapply --numstat validate generated path completeness, exact owners and text-only counts. There is no manually supplied patch parsing endpoint. NUL-bearing source and binary generated diffs fail. Valid ++/-- counter and raw-string lines, empty indexed files and mode-only diffs are handled by Git's own parser.

Manifest bytes, HEAD/index/status, every assigned source hash and existing destination patch hashes are rechecked before output publication. Missing or unstable foreign sources fail before patch rewrites. All outputs are prepared first; replacement is atomic per file with ordinary I/O rollback, not a process-kill/power-loss multi-file transaction. Actual mutation must still run under locked.sh against stable inputs.

Validation: `python3 -B arc/browser/webextras_nested_regeneration_test.py` passes26 private real-Git cases. The main fixture applies all five exact reviewed frontend source changes plus actual native bindings, an indexedITA hook, and an independent foreign C++ edit containing decrement/increment and raw-string header-like lines. It proves deterministic regeneration→UNCHANGED ORIGINAL sync loop clean apply→already-applied skip→reverse byte identity, with both Git indexes unchanged. Other positives cover nested-only/outer-only/mixed patches, outerALT-only addition with nested actual index, staged/worktree disagreement, forcedcolor override, empty indexed new file, mode-only diff, and original sync partial-apply failure without partial mutation. Negatives cover binary source/generated binary diff, destination patch drift, hidden flags, untracked/duplicate/escape/missing/symlink sources, moved nested/index gitlink, inherited Git context and source drift. Exact command logs, byte hashes, original sync hash and strict direct forward/reverse reconstruction of the two proposed files are in logs/wp/webextras-nested-regeneration/.

This is patch-persistence tooling only. Frontend host gating is handled by a separate peer proposal. Feature declaration, actual frontend resource build/package, launch-slice9/9 and own-scenario no regression remain required after authorized integration. No Root/cache/e00 activation, native engine runtime, scenario diff or acceptance is claimed.
