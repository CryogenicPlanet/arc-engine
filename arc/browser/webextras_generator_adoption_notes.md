# Private standalone generator adoption preparation

This owned driver is private preparation. The emitted template is UNSEALED: successor pins, owner ACK, review, epoch guards and parent-held state are unset. No production epoch was captured, no production-checkout Git command or lock was used, and no shared tool was adopted. It does not activate held Media/DevTools work or launch any engine, build or scenario.

The action is exactly old wrapper `dabcc525` plus absent helper to two separately reviewed/pinned successor images. Candidate pins are configuration data, not hardcoded adoption authority. Copied positive tests bind proposal `22ea77b1`, wrapper `a5dda448`, helper `d40e1002` from the racy successor. That proposal's approval is separate from this driver's review. Frozen303 and env-only26 remain historical;26's private-index timing counterexample remains in this log directory. No production output is inferred from that fixture.

## Boundaries and admission

`template` emits an unusable config. A future authorized epoch must provide the exact complete config, canonical indent-2 JSON with final newline, its SHA, immutable source/proposal/review/ACK/parser/executable pins, physical preimages and all inventories. `validate` only validates supplied data and read-only files; it neither creates an epoch nor grants approval. The driver intentionally provides no capture/auto-seal command.

`run` verifies canonical sealed config bytes before creating a fresh owned run directory or launching anything. The protected process ignores INT/TERM/HUP and execs the existing `/bin/bash arc/tools/locked.sh`; the lock owner remains that process. The same guardian owns all admission and release decisions. Every guardian bootstrap error, including config/output/launch failure after the lock wait, enters HOLD. The guardian never reconstructs its own admission state after worker exit.

After acquiring and proving the lock, and BEFORE spawning a worker or running any oracle/preparation/publication/regeneration, the guardian durably writes `admission-request.json`. The parent must independently write `admission.json` with exactly the requested action, request SHA/nonce, config SHA, launch nonce, guardian PID, lock stamp and physical current held-state identity, plus `decision: ADMIT` and literal `ready: true`. A prewritten/stale/nonboolean receipt refuses; elapsed time supplies no approval. This new admission is required even if the sealed owner ACK was previously obtained, preventing admission based on a peer parent that has already reaped the intended transaction. Parent state and admission remain guarded throughout.

The guardian writes a fresh worker nonce/intent before spawning one worker, records the actual child PID, and reaps it. The worker requires its actual parent PID, exact intent/nonce and own PID receipt before any work. The same guardian checks the actual reaped child against that record; there is no detached second guardian.

## Oracle and guards

All subprocess Git uses the exact trusted App8 environment: PATH=/usr/bin:/bin, LANG=C, LC_ALL=C, GIT_OPTIONAL_LOCKS=0, GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_SYSTEM=/dev/null, GIT_CONFIG_GLOBAL=/dev/null, GIT_ATTR_NOSYSTEM=1. Config pins distinguish the driver runtime, `/usr/bin/python3` launcher, its resolved Xcode Python runtime, `/usr/bin/git`, `/usr/bin/env` and `/bin/bash`. After admission the exact env-i App8 launcher reports only its real runtime path, which must equal the pinned runtime before preparation/publication, as a mandatory recorded command with fully drained completion. The macOS launcher can add platform SDK variables; the successor helper's Git ENV remains exactly App8.

The read-only canonical calculation loads only the reviewed pinned helper source, uses its manifest/repository/private-index/ownership/numstat validation routines, and explicitly calculates HEAD-to-worktree diffs. It never calls publishing `generate` or `regenerate` as a dry run, and never copies the entire Chromium checkout. Every maintained generated patch must already byte-match the canonical outputs before either tool changes; the real wrapper must reproduce those bytes, and a second canonical calculation must agree. All patch inventory, source/MANIFEST and configured guards remain physically unchanged.

The full-index logical parser is the exact 70-line pure App444e parser, attributed through its four original policy pins; no App driver is imported. Every original root/native/nested index is sealed by full raw SHA, inode/device, mode, size, mtime/ctime, HEAD and logical entries/flags. Split/shared/indirect index layouts are rejected. Unlike a stat-relaxed boundary, this standalone transaction requires the ORIGINAL full raw and physical identity for the entire regeneration, on success AND error. Atime is excluded and never restored.

A lease is durably OPEN before each oracle/official command and CHECKED only after the exact original index/HEAD/logical proof. Any mismatch latches irreversible HOLD; failed latch storage leaves OPEN. A new guardian cannot reinterpret either as safe. Command SPAWNING/RUNNING records are written before/after spawn, complete groups are drained even when bookkeeping fails, and DRAINED/CHECKED hashes are saved at the write that produced them. Completion requires the unchanged exact operation inventory; adoption requires all five command exits0 and three leases exit0/errorNone, with fixed argv/label/file/worker/config bindings. Missing records and relabeled errors cannot release through adoption; physically guarded tool/index/source substitutions are also rejected even when bytes match.

Mandatory guards include all production API/browser/wp source inventory, manifest native leaves, all maintained patches/MANIFEST, build scripts/config, built and packaged ArcCore engine/resources, exact helper/plist inventories, packaged app/plist, and recorder. Both lexical and resolved app/framework process prefixes and all owned groups must be drained. Current built/package binary inputs are fixtures in tests, not live qualification.

Per direct repository, local `.git/config`, `info/attributes`, `info/exclude`, and every assigned-leaf ancestor `.gitattributes`/`.gitignore` are guarded including absence. Effective App8 config-origin output is SHA256 hashed in memory; values are never logged. Included/conditional/external config origins, external attributes/excludes, worktree config and indirect `.git` layouts are explicitly unsupported and HOLD/refuse. These checks run after admission before preparation, before/after each lease, and before reversion/certification. Metadata is never restored.

## Publication, failure and persistence

The two-file proposal is strictly reconstructed in a private tiny Git repo with whitespace=error and exact postimages. Prepared files use exclusive creation, fsync, exact modes and physical identities. The driver checks destination preimages and saved prepared inodes, publishes HELPER FIRST then WRAPPER SECOND, and checks each resulting inode (only rename-induced ctime may differ). It rechecks owned tool identities immediately before and after the actual wrapper command.

On an ordinary pre-adoption failure with unchanged source/patch/index/metadata and proved owned images, only the two tools may be conditionally reverted. The old dabc regeneration is NEVER invoked as recovery; no source, metadata, patch or index restoration occurs. Partial publication rolls back only proved own images. Foreign source/index/patch/build/tool conflicts, uncertainty around publication, missing/drifting evidence, receipt failure at commit, OPEN/failed leases, or live groups retain the lock in HOLD. HOLD itself tolerates receipt-write/post-proof failure. There is no automatic lock removal or forced process killing.

A successful `adopted.json` is a persistent generator-baseline receipt independent of any later engine journal; this action never starts one. Later engine rollback must retain adopted tools. The same guardian alone writes `release-safe.json` after full proof. A failed receipt cannot be downgraded into a normal tool reversion after the commit attempt.

## Verification limits

Tests use copied actual scripts, real Git in disposable outer/native repos, exact reconstruction/oracles, synthetic owner ACK/config, fake fixed-role binaries and mocked lock/process census. Actual protected/guardian main paths are exercised with mocked exec/spawn to prove order and same-instance decisions; no production lock is invoked. Fixtures default to actual same-size immediate edits (`racy=True`) against the corrected successor; an explicit nonracy positive is separate. The original env26 timing failure and earlier failing test logs are retained. This prepares a transaction for independent review; it does not prove production oracle equality, approval, actual lock behavior on this epoch, OS exit, engine integration or package scenario acceptance.
