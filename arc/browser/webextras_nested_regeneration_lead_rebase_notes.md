## Lead-compatible index and root contract

The copied shell wrapper retains the lead's explicit context cleanup and real-checkout root guard, additionally clears all inherited `GIT_*` variables, and sets `GIT_OPTIONAL_LOCKS=0`. Physical `pwd -P` makes the guard compare the actual checkout path even through macOS `/var` aliases. The helper independently sanitizes inherited Git environment before **any Git discovery** and derives root from its own file location. There is no caller-root argument, inherited index option, index restoration policy, new applier or sync change.

For outer Chromium and, when manifest-selected, the one known `third_party/devtools-frontend/src` checkout, Git discovers the real index first. Its bytes/path/inode/size/mtime/ctime and HEAD are pinned. Stage0 entries and ordinary index flags are checked. The actual outer HEAD gitlink, real outer index gitlink and nested HEAD must agree; the nested checkout/index is discovered independently. A private temporary directory receives separate byte copies of those actual indices, rechecked during copying. Only these internally selected private indices receive `git add --intent-to-add`, and only for exact manifest-assigned regular text leaves absent from both the real index and the owning repository's HEAD. Existing HEAD-tracked leaves missing from the real index are refused. Existing real ITA entries remain valid. Unassigned/untracked changes, symlink/escape/missing/binary sources and hidden/conflicted/rename/delete state fail before output publication.

Real indices are never refreshed, staged, restored, or replaced. Their original physical identity is checked throughout publication; changed bytes and same-byte index replacement both reject without adopting or restoring the external state. Inherited `GIT_INDEX_FILE`, `GIT_DIR`, `GIT_WORK_TREE`, object/common-directory, namespace/prefix, config and trace context cannot redirect discovery or private operations. Caller-created alternate indices are ignored, including valid empty, corrupt, relative and empty values.

Existing split real indices are conservatively unsupported, preventing private add-N from causing shared-index side effects in the real gitdir. Private Git commands disable split-index creation. The read-only detection query explicitly enables split detection: observed Git2.50.1 returns an all-zero40/64 shared-object placeholder for an unsplit index, while a nonzero/malformed link is refused even if its shared file is missing. No handwritten binary-index parser is introduced. This is a bounded normal-index contract, not a general Git environment/framework claim.

## Serialization and publication

Manifest syntax remains `<patch basename> <outer Chromium relative leaf>`, exactly once per source. The one supported nested checkout is explicit. Native and frontend changes are generated by actual Git **diff HEAD**, meaning final staged-plus-unstaged worktree contents, with external diff/textconv/renames/color disabled. Nested diffs carry full outer `a/third_party/devtools-frontend/src/` and `b/.../` prefixes. No frontend resource/build dependency changes are part of this tool proposal.

The HEAD-tracked-never-new guard uses owning-repository Git `--name-status` metadata and HEAD presence. Trusted generated output is checked with Git's own `apply --numstat` for text-only paths, exact owners and completeness. There is no unified-hunk/header parser or arbitrary-patch apply API. Valid source hunks containing apparent `--- /dev/null` and `+++ b/<tracked path>` lines cannot trigger the guard.

All outputs are prepared before publication, after source/manifest/HEAD/real-index/status/destination hashes are rechecked. Already identical patches are not replaced, preserving their bytes and metadata for a tools-only no-change oracle. Changed outputs use same-directory temporary files and atomic per-file replacement. An ordinary I/O failure rolls back only already-published files, also through atomic replacement; preparation failure does not touch existing outputs. This is not a power-loss/process-kill multi-file transaction and does not replace the integration lock protocol.
