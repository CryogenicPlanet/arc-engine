# Held resource result binding correction

This distinct increment supersedes the resource-binding readiness of the frozen 8a14 proposal; it does not modify any original proposal file. Apply only after that exact proposal, never as an alternative base. The staged TS postimage adds one assertion after the actual checker returns and before either cleanup receipt publication or verified status: the returned resource identity must equal the in-memory launch resource identity. Existing before/after disk-journal checks remain.

The peer's actual TS/checker control transiently replaces the disk journal during verification, then restores it before the second disk check. Frozen b3dc source accepts a different current PAK identity as verified-unchanged. The corrected source records changed-or-unverifiable, retains the returned diagnostic object and records the mismatch error; it publishes no verified cleanup receipt. This is a receipt-binding correction, not a claim to prevent arbitrary concurrent filesystem changes between observations.

`webextras_resource_binding_correction_test.py` compiles the pinned original actual resource test in memory, injects the peer's transient-journal control and runs it against both the immutable baseline and staged postimage. The frozen old negative control deliberately proves the false pass; the corrected control requires rejection and no verified receipt. Existing actual clean, original-layout, mutation, earlier-error preservation, persistent rewritten journal and checker mutation controls run in both cases. All fixture trees are private temporary directories. No app, shared lock, build, package, profile or runtime observation was touched.

The old 8a14 freeze, scripts and checker remain byte-identical. A future adopted wrapper must use this corrected TS postimage and a newly sealed complete source manifest. Native13 source/config pins remain UNSEALED pending initial material source adoption, peer review and parent queue authority. Comparison policy, quiet deadlines, helper bytes and resource inventory format are unchanged.
