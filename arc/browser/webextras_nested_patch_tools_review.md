1. **P2: assigned file changes can be silently dropped by index flags.** The staged helper's `entries()` at lines 65–74 records mode/OID/stage but does not reject assume-unchanged or skip-worktree. `validate_sources()` uses status, and generation at lines 163–164 uses `git diff HEAD`; both honor these flags. Applying the output also returns 0 but leaves `int foreign = 1;`. Expected SHA256 is `08aca1b069f759f5ad76e50ea50523918691585b2f41a445853d91ca9b4bb425`; replayed SHA256 is `d3d04d4663da3ae84e79fd901bb7496318430c114aa4bec0b819620c85ac6ef4`. Both indexes remain byte-identical during the tool invocation. Reject these hidden flags before publication, or generate a comparison that independently includes the required final worktree bytes.

2. **P2: binary input publishes an unusable patch instead of failing closed.** A NUL byte in the same assigned file makes generation return 0 and replace the foreign output with a `Binary files ... differ` record. The proposed apply helper then rejects its own output with `unsupported patch format` (exit 2). This violates the notes' bounded contract that binary inputs fail, and can destroy a previously retained usable foreign patch. Validate every generated patch's supported text format before any output replacement; binary support is not required.

3. **P2: `color.diff=always` corrupts generated patches.** The diff invocation lacks `--no-color`. With that ordinary Git setting in the outer fixture, regeneration returns 0 and publishes ANSI escapes in the output. The proposed apply helper rejects it with `No valid patches in input` (exit 2). Explicitly disable color for generated diffs and retain the generated-format validation above.
