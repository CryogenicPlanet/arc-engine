# HELD nested frontend patch tooling proposal

Proposal `webextras_nested_patch_tools.patch` SHA256970b751b2b666327c4c80e702bfbc1eb7a8ac8ff4c83861f1217d1884db36885 changes shared tools only: arc/tools/regen-patches.sh and sync-chromium.sh delegate to new arc/tools/chromium-patches.py. It is staged privately under logs/wp/webextras-nested-patch-tools/staged; actual shared tools, real Git indexes, MANIFEST, Chromium, maintained patches, apps and build/runtime state are untouched. Lead ACK is required for these exact shared-tool files. No initial DevTools proposal is rewritten or activated.

Manifest syntax remains `<patch basename> <outer Chromium relative leaf path>`, with exactly one owner per file. Existing hooks.h/window stay0004-arcmod-hooks.patch. Four native dispatcher/bindings files and five frontend leaves should each be assigned once to0010-webextras.patch in a separate authorized integration. The helper recognizes only the existing gitlink third_party/devtools-frontend/src; arbitrary nested repositories are not supported.

Regeneration validates outer HEAD gitlink, outer index gitlink and nested HEAD equality, independent nested root identity, stage0 regular indexed leaves and no symlink path components. Tracked intent-to-add entries are valid. Every assigned input must exist; unknown/untracked changes, duplicate owners, escapes, renames, deletions, conflicts, unsupported modes, moved gitlinks and unassigned changes fail before output mutation. Both worktrees are explicitly inspected with NUL porcelain and ignore-submodules=none regardless of local ignore settings. Every Git read has GIT_OPTIONAL_LOCKS=0. Diff disables external drivers/textconv/renames.

Each patch combines ordinary outer diffs and nested diffs with full `a/third_party/devtools-frontend/src/` / `b/...` prefixes. It uses `git diff HEAD`, so staged plus unstaged changes produce final worktree bytes. This deliberately differs from the old unstaged-only diff, and the fixture proves staged/worktree disagreement preserves the worktree result. Neither real nor temporary indexes are written by the tool. **All regeneration sources must already be indexed, including new outer additions via explicit authorized intent-to-add bookkeeping.** Untracked sources fail even if listed in MANIFEST. Unlike the old script, this helper never runs git add -N. Sync apply creates new outer files without staging; a later regeneration of those additions requires explicit indexing first. This stricter contract is part of the requested lead ACK.

Manifest bytes, both HEADs/index bytes/status, every assigned source byte hash and all destination patch hashes are checked before generation and again before publishing. Missing foreign sources fail closed instead of erasing retained foreign patch content. The build lock is still mandatory; these checks detect concurrent drift and do not provide a filesystem transaction. All output bytes are prepared before replacement. Replacements are atomic per file, with rollback on ordinary I/O errors; process kill/power loss can interrupt a multi-file publish, so rerun under the lock against unchanged pinned inputs before syncing. This is not a multi-file atomicity claim.

Sync keeps existing patch order and already-applied semantics but validates ownership, text paths and regular modes. It freezes each patch's bytes in memory, then uses exactly those bytes for numstat, reverse-check, forward-check and application. The actual outer `git apply` worktree path is used without --index; the fixture proves it applies frontend leaf hunks across the gitlink. Fully applied patches skip; partially applied patches fail without partial mutation. Binary patches, rename/copy/delete operations, unsafe modes and symlinks are outside this bounded contract and fail. Empty owned patches are skipped.

Validation: `python3 -B arc/browser/webextras_nested_patch_tools_test.py` passes24 tests in private real Git repositories. The main fixture starts from five exact initial-pipeline frontend sources plus actual DevToolsUIBindings.cc, applies their exact reviewed intended output bytes, preserves an independent foreign native edit, and includes an outer indexedITA hook header. It tests outer-only, nested-only and mixed patches, stable regeneration, clean-checkout sync through the proposed shell loop, already-applied skip, reverse-check/reverse and full byte identity. Both Git indexes remain unchanged. Local diff.ignoreSubmodules=dirty and an intentionally unusable external diff driver cannot hide/suppress the nested diff. Negative tests cover missing foreign source, unknown and manifest-listed untracked files, duplicate/path escape entries, symlink leaf/parent, moved HEAD/index gitlink, rename, wrong owner, unsafe mode, external patch path, partial application and deterministic source drift before publication. Exact commands/results and roundtrip hashes are under logs/wp/webextras-nested-patch-tools/. Strict forward/reverse application reconstructs all three staged tool bytes exactly from actual tool bases.
