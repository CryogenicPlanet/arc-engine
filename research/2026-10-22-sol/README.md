# Sol research orchestration

Created Oct 22, 2026 by the Codex lead at Rahul's request. This directory is the durable handoff for the remote research, not a claim that the engine feasibility work is finished.

- `arcmod-engine.exe.xyz`: existing standalone 16 vCPU / 32 GiB. READ ONLY from this harness. Ghidra decompiles ArcCore 1.170.0 there. Never stop, pause, restart, resize, or alter it without Rahul's explicit authorization.
- `arcmod-research.exe.xyz`: new VM in the existing `default` 2 vCPU / 4 GiB pool. Four GPT-6.1-Sol agents use the ChatGPT-backed `llm` integration. No additional compute reservation was created. Its local disk is independent of the engine VM. All agents share the input snapshot and have separate output directories.
- Roles: `abi` (declared API vs verified app calls), `cef` (pinned CEF mappings), `arc-layer` (Arc-specific inventory and bootstrap), `matcher` (repair and validate stock Chromium comparisons).
- Primary input identity: ArcCore 1.170.0 arm64 SHA256 `69276adaca785a46f2554e7fd18926e7fcdd6aba44ba64400a337427817db3dd`; pristine app 1.168.0 executable SHA256 `4c03750e2a2c4f8843dec4b90db2e0f1c5e4ba01ef2140e3961a6194bcc9d682`. Stock baseline SHA256 `39647a537f42460da18576c0a5856171dfec2250ed505698dbbdd99a40b75645`, 642,894,320 bytes, verified on source and destination. The older file named `local-arccore-156-arm64.sha256` actually hashes ArcCore, not this stock baseline.

Run `python3 orchestrate.py status` for current jobs and main decompile progress. `collect` retrieves reports, evidence and scripts into ignored `collected/`; it does not retrieve the large input tree. Remote `~/work/STATUS`, `~/work/logs/<role>-<stage>.jsonl`, `~/work/out/` and `~/work/agents/<role>/<stage>/report.md` are the source of truth. A `DONE` marker means a CLI run produced a fresh report; it is not independent validation of its conclusions. Inspect JSONL `turn.completed`/`turn.failed` events and actual artifact content.

Initial workers use metadata and the existing APP decompile. ENGINE C output is held in memory until the main export completes. Once `PHASE B DONE` and final `DecompileAll: done=...` are present, collect and inspect initial reports and shard requests. Put reviewed extra shard basenames (one `0x<hex>.c` per line) in `reviewed-shards.txt`. `feed-decompile` selects named Arc-method shards plus Arc source/IPC-reference shards and the explicit requests; transfers from the main VM through the Mac; verifies per-file SHA256; publishes one immutable batch; launches second-stage workers only when each initial stage is complete. Repeating it skips the transfer and tries pending launches, guarded by per-role locks and completion markers.

If a second-stage report needs additional unnamed callees, review its `additional-shards.tsv`, replace `reviewed-shards.txt` with the approved basenames, and run `feed-extra`. This publishes a separate immutable `inputs/decompile-extra/batch-.../` with a manifest and READY marker. It deliberately does not mutate evidence being read by workers. The lead must then run/resume targeted Sol analysis with the explicit batch path and a fresh output/report name, verify completion, and review the result. Do not delete a prior `.done` marker to fake a new run or blindly repeat a failed run.

After all four decompile reports are complete, `launch-review` runs a fresh Sol reviewer, then `collect` retrieves its `synthesis/engine-feasibility.md` and findings. The parent must assess this evidence, resolve material issues, and write the final project feasibility note. No native app changes, commits, pushes, resource lifecycle changes, or messages outside the authorized Chirp board are part of this harness.

The lead's thread heartbeat `arc-engine-sol-research` runs every 10 minutes and continues the work across turns: inspect meaningful changes, dispatch prerequisites, collect/review results, and stop the heartbeat when synthesis and follow-ups are complete or user action is required. Stay quiet while nothing actionable changes. Keep the research VM/data intact; pausing/deleting requires Rahul's specific approval.
